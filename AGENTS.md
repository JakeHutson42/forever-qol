# Forever QoL visual standard

Apply the `ui-visual-fidelity` skill by default when creating or changing anything a player can see or interact with. When the user supplies a template to follow or copy, use its matching layout, control construction, visual states, materials, and proportions as the implementation target. Preserve Forever QoL's content and branding where the template leaves room for it. For settings, start from the installed FlareUI `Settings/Panel.lua` at `C:/Program Files (x86)/World of Warcraft/_forever_/Interface/AddOns/FlareUI`. For other surfaces, use the user's named template or the corresponding part of the installed reference. Use game-native equivalents or original artwork for assets unavailable for redistribution.

- Settings should make controls easy to find and understand. Use a coherent header, clear navigation and selected states, readable section hierarchy, aligned controls, and contextual help or realistic previews where a setting benefits from them. Keep controls usable on a compact viewport.
- Match HUD components to the same visual standard. Judge textures, frames, borders, fills, text, and empty tracks together at their shipped sizes. Verify partial fills and thin bars before choosing a texture. Use motion for meaningful feedback and preserve legibility over both bright and dark gameplay.
- Compare the implemented screen side by side with the reference in WoW at the user's usual UI scale. Check the same state, including empty or populated content and hover where applicable. If the client is unavailable, inspect the geometry and an available render, then report the build as ready for client testing. Functional checks and mock renders cannot establish a visual match.
- Apply this standard to the affected surface and its shared components. A quality pass does not expand the feature scope into unrelated screens, functionality, or deployment.
